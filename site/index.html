Can we rely on this vendor's SOC 2 report?

A third-party risk tool that reads the report twice, once with text patterns and once with Claude, checks every disagreement against the page it came from, and leaves each decision to a person.

What this page is
A summary of a working project, with a demo on a fictional report. Real reports are restricted-use documents and stay off the internet.
Why it matters
The scope page named all five categories in the title of the criteria, then applied one. Pattern-matching took the title.

What reading twice caught

A bug in the pattern reader, which counted a legend sentence as a test result. And a mistake in the answer key itself: it had no untested controls, while Claude found seven results reading "No testing performed". Untested controls are not evidence that controls work. The key was corrected after the run, and the correction is recorded.

The decision model that checks disagreements

Jev, a decision model from TypeSafe, answers one yes-or-no question per disputed value: does this page support it? It never sees counts or dates, which its own documentation says it handles poorly. In a test of 46 questions mixing true values with deliberately planted wrong ones, it accepted no wrong value and rejected no true one; three answers were unsure and went to a person.

Model
claude-opus-5-5, structured JSON, one run per route.

Decision model
jev-1.14.0; yes at 0.8 or above, no at 0.2 or below, a person in between.

Limits
Two reports. Answer keys not yet checked by a second person.

How a review runs

  1. Read the report twice. The pattern reader and Claude each return the same fields, every value with the page it came from.
  2. Compare the readings. Any field where they disagree goes to a queue. A disagreement that changes a reliance rule blocks the merge.
  3. Check the page. Jev reads the cited page and suggests which reading it supports. The suggestion is advice; it resolves nothing.
  4. A person resolves each disagreement by taking one reading or typing the value from the page. Every resolution is logged and bound to the exact pair of readings.
  5. Apply the reliance rules. Period and staleness, bridge letters, scope against the categories you need, carved-out providers, owners for complementary user controls, test exceptions.
  6. A person approves or rejects each finding. Nothing is a finding until then. Decisions are appended to a log, never overwritten, and tied to a hash of the reading they were made on.
Sources
Each rule cites a published source: the 2023 interagency third-party risk guidance, GDPR Article 28, NIST SP 800-53, and a practitioner SOC 2 review method. Values a regulator leaves to you are marked as your policy.

Cost on real reports
Claude: about $0.003 to $0.004 a page. Jev: well under a cent a review.

The rules, in plain words

The tool uses rules twice. Reading patterns pull facts out of the text: the date range after "for the period", the categories named as applicable, each line saying "No exceptions noted". They are free and instant, and brittle: built on one auditor's layout, they scored 10 of 27 on another's. Claude reads the same fields; where the two readings disagree, a person decides.

Reliance rules then turn the facts into proposed findings. Each one names its source.

Changing the rules

The numbers regulators leave to each organization, such as when a report counts as stale or how long before a bridge letter is needed, sit in one policy file you can edit. Your context (the categories you need, the provider reports you hold, who owns each customer control) changes which findings apply; try it in step 4 above. A new kind of rule today means a few lines of code and a test.

Sources
Thresholds come from an MIT-licensed practitioner SOC 2 review method; regulatory anchors are the 2023 interagency third-party risk guidance, GDPR Article 28 and NIST SP 800-53.

What it will not do

  • Decide on its own. Every finding and every disagreement waits for a named person.
  • Pick a winner when readers disagree. It stops and shows both, with the page.
  • Trust a measurement it has not made. Claude and Jev are scored against answer keys before anyone relies on them.
  • Put real reports online. The tool runs on the reviewer's machine, and real reports, answer keys and results stay there.
